# Meridian web application

For production hosting, follow [DEPLOYMENT.md](DEPLOYMENT.md).

Run `run_web.bat` from the repository root, then open http://127.0.0.1:8000/. The batch file uses the repository virtual environment to serve the FastAPI API and the built React application. After frontend changes, run `npm run build` in `web/frontend`.

The public `/overview` route shows aggregate traffic statistics, camera analysis, charts, and insights from the configured simulated Hyderabad camera network. Registration numbers, evidence, vehicle search, tracking, and ANPR uploads require an operator session. Both the React routes and FastAPI endpoints enforce that boundary.

Operator registration and login accept addresses with a local part ending in `.cop`, such as `sriram.cop@gmail.com`. The backend validates the rule independently of the form.

The console accepts up to 10 images per batch or one video. Video processing samples three frames per second by default at the full 1280-pixel detector input to retain distant-plate coverage. OCR skips slower threshold variants when the two natural-image reads already agree; uncertain reads also check an adaptive-threshold pass and retry on the tight plate crop. Indian registrations with up to three series letters are supported. Set `ANPR_VIDEO_SAMPLE_FPS` and `ANPR_VIDEO_INFERENCE_IMG_SIZE` to tune the speed/detail tradeoff. Similar plate strings merge only when their tight plate boxes also track together across nearby frames. A local OCR quality score strictly above 94% is automatically accepted without a Gemini request. At 94% or below, Gemini must return the same normalized registration for automatic acceptance; disagreement, unavailable Gemini, or a missing key sends the observation to the authenticated `/reviews` queue. The review ledger retains both reads and their original scores. Reviewer-confirmed sightings are saved with their original observation time and appear in Vehicle Tracking even when only one camera has recorded them. Route lines follow camera observation order with a maximum 12-hour gap; all sightings remain visible in the timeline. Bell alerts are enabled by default for new pending observations; browsers may require an initial click or key press before audio can play.

`ANPR_GEMINI_API_KEY` enables Gemini as a second reader for available cropped plates scoring at or below 94%. Gemini is prompted only to read the registration; it is not asked to identify vehicle color or body style. On Windows, the server can also read a key from `%LOCALAPPDATA%\Meridian\gemini.key`; on other systems it can use an ignored `web/backend/.gemini-key` file. An existing `ANPR_GOOGLE_VISION_API_KEY` remains supported as a fallback when Gemini is not configured. Keys remain server-side. Agreement with Gemini accepts reads scoring at or below 94%; disagreements, unreadable results, or unavailable Gemini stay pending. Local OCR scores above 94% are accepted without a Gemini request. Provider reads run with bounded concurrency before the review database is locked. No key is required for the local YOLOv8/RapidOCR pipeline; Tesseract remains a fallback. Detector confidence describes the plate-region detector; OCR confidence and video frame agreement are separate quality signals, not calibrated probabilities of a correct identity.

The review screen shows the observed camera, location, time, source, video frame count, alternate reads and nearby registration candidates. These are review aids, not an automatic vehicle identity or verified route. An operator can optionally record a color observation with a decision; it stays in the private review ledger and is not used for cross-camera matching.

The site shows recorded observations from uploaded media and a simulated camera network. It does not connect to live cameras or infer motion between sightings.
